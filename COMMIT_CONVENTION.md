# Коммит-сообщения (Commit Convention)

## Общие правила

После выполнения каждого задания нужно делать `git commit` с понятным и структурированным сообщением.

### Формат сообщения

```
<тип>: <описание>

[опционально] Детали изменений
```

### Типы коммитов (типы)

| Тип | Описание | Пример |
|-----|----------|--------|
| `feat` | Новая функциональность / задача выполнена | `feat: реализован пример 3+4=7 в кроссворде` |
| `fix` | Исправление бага или ошибки | `fix: исправлен расчет результата для деления на 0` |
| `docs` | Изменения документации | `docs: обновлено руководство пользователя` |
| `style` | Форматирование кода (Prettier) | `style: пропущено форматирование стилей TS` |
| `refactor` | Переписывание без добавления фич/фиксов | `refactor: упрощена логика в reducer` |
| `chore` | Другое (конфигурация, зависимости) | `chore: обновлен .gitignore` |

### Примеры хороших коммитов

```bash
git commit -m "feat: реализован пример 3+4=7 в кроссворде"
git commit -m "fix: исправлено отображение результата при делении на 0"
git commit -m "docs: добавлены инструкции для родителей в README"
```

### Структура сообщения (для больших изменений)

Для крупных обновлений используйте многострочное сообщение:

```bash
git commit -m "feat: реализован пример 3+4=7 в кроссворде

- Добавлен новый пример в массив данных
- Обновлены тесты для нового кейса
- Проверено форматирование с Prettier"
```

## Автоматизация

Для автоматического коммита после выполнения задания используйте скрипт:

```bash
npm run commit:after-task
```

Это создаст commit с сообщением в формате: `<тип>: задание выполнено — <описание>`

### Как использовать скрипт

1. Выполните задание
2. Введите описание изменения (или оставьте пустым для auto-generate)
3. Скрипт автоматически создаст и применит коммит

## Чек-лист перед коммитом

- [ ] Код отформатирован (`npm run format`)
- [ ] Прошел линтинг (`npm run lint`)
- [ ] Тесты проходят (`npm test`)
- [ ] Коммит-сообщение описывает именно что сделано, а не что будет
